## 二、高可用项

### 1. 优雅停机

`server.py` 处理 `SIGINT/SIGTERM`：收到信号后 `srv.shutdown()` 停止 accept、等待在途请求完成再退出。Docker 场景下 `docker stop` 可获得干净退出。

### 2. 健康检查

- `GET /healthz`：返回 `{status, mode, version, model_loaded, uptime_s}`。
- `GET /readyz`：就绪探针（检查评分器已加载、数据目录可写），就绪返回 200，未就绪返回 503。K8s 可配置 liveness / readiness 双探针。

### 3. 无状态化

网关业务状态仅存在于：审计 `audit.jsonl`、监控 `monitor.jsonl`、训练产物 `engine_model.npz`。引擎模型启动时从 npz 加载，`--retrain` 显式触发重训；多实例水平扩展时审计/监控追加写需外部卷（联邦部署项），单实例下启动即热。内存：进程常驻峰值约 150–250MB（含 300k ANN 索引与 Web 控制台），压测期间无泄漏迹象。

### 4. Prometheus/Grafana 指标

`grafana/dashboard.json`（Grafana 8+ schema，Prometheus 数据源变量）：

| 面板 | 指标 |
| --- | --- |
| 请求吞吐 QPS（按档位） | `fg_router_requests_total` / `fg_router_tier_requests_total` rate |
| 端到端延迟 P50/P95/P99 | `fg_router_request_duration_seconds_bucket` histogram_quantile |
| 上游失败计数 | `fg_router_errors_total` |
| 漂移告警总数 | `fg_router_alerts_total` |
| 语义向量模式 | `fg_router_embedding_mode` |
| 路由成本支出 | `fg_router_cost_usd_total` rate |
| 评测代理成本 | `fg_router_judge_cost_usd_total` rate |

接入：Grafana → Data sources → Prometheus（`http://<gateway>:8000/metrics`）→ Import dashboard.json。

## 三、单实例 SLA 基线（基于实测）

- 吞吐：≥ 300 QPS（8 并发实测 404 QPS）
- 延迟：端到端 P95 < 100ms（实测 34ms @ 8 并发）
- 可用性：healthz/readyz 双探针 + 优雅停机，容器内 99% 以上滚动发布
- 兜底：上游失败自动降级、单请求异常隔离

限制：多实例负载均衡、持久化卷、监控告警规则（Alertmanager）属联邦部署项，未在本报告覆盖。
